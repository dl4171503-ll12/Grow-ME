# 给其他 Agent / 其他编辑器接入（porting）

grow-me 是纯 Markdown 规则，无运行时依赖。三种接入方式，按"常驻强度"从强到弱。

## 方式 A：技能目录（最适合 Claude Code / Codex / DSH / Cursor Agent）

```bash
# 个人级（所有项目生效）
cp -r grow-me ~/.agents/skills/grow-me      # 本机实际路径：C:\Users\<you>\.agents\skills\
# 或项目级
cp -r grow-me <repo>/.agents/skills/grow-me
```

放入后新会话自动出现在技能列表。想只在点名时生效，在 frontmatter 加
`disable-model-invocation: true`；想常驻（默认）就别加。

## 方式 B：仓库规则文件（最适合团队共享、强制常驻）

把下面这段粘进 `AGENTS.md`（Codex）、`CLAUDE.md`（Claude Code）或 `.cursor/rules/grow-me.mdc`：

```markdown
## 工作协议（grow-me）
1. 先建 `.grow-me/<日期>-<slug>.md` 工作记录（目标/验收、决策、事实带 路径:行号、验证、DAG、下一步），再动手；每推进一个节点更新一次，回复只留摘要。
2. 动手前：能自己查的事实不问你；要你拍的决策一次问清（≤5 问，每题带默认值）；用户不回按默认推进，放行后才写代码。
3. 上下文纪律：先检索后精读，不整目录通读、不重复读、不把大段内容贴回；长输出落 `.grow-me/logs/`。
4. 五维工件：验证命令清单 / 任务 DAG / 每节点 3 行规格 / 事实节 / 循环预算（每节点 ≤10 次工具调用、≤2 次重试）。
5. 收尾给五段：进度图 / 本轮 / 证据 / 下一步 / 阻塞 + 记录路径；达标即停。
6. 红线：不留占位符、不把活推回用户、没跑过不说通过、不缩范围、不重复读文件、不为显得勤奋多跑命令。
```

## 方式 C：一次性 Prompt（不适合长期）

把 `SKILL.md` 前 60 行贴进对话开头即可。缺点是每个新会话都要重贴，且容易被后续长对话冲淡 ——
只在临时环境用。

## 兼容性注意

| 环境 | 注意点 |
|---|---|
| 能写文件的 agent | 直接按规则建 `.grow-me/`，最省 token |
| 不能写文件（纯聊天） | 把"记录"降级为回复末尾的折叠块，仍保持"结论进记录、过程不入上下文"的精神 |
| 没有 grep/glob | 用行号范围读文件，仍然遵守"有目的才读、不重读" |
| 多 agent 协作 | 每个 agent 读同一份记录；写入用"就地覆盖小节"避免冲突，或按 agent 分节追加 |

## 自检：接得对不对

接入后随便给一个多步任务，观察三件事：
1. 有没有先建 `.grow-me/` 记录再动手？
2. 有没有在一次读取里翻整个目录 / 重复读同一文件？
3. 收尾有没有五段尾巴 + 记录路径 + 真实命令输出？

三条都满足 = 接入成功。
