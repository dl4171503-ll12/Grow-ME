# minmind 预训练工作台规范（规则九配套）

> 用于"用 minmind 数据训练大模型 / 完成第一阶段预训练 / 把 loss 从 8.76 压到 2~3"这类任务。
> 控制台读取本规范产出的 `loss.csv` 与 `runs/` 备份目录。

## 目标与验收

| 项 | 验收标准 |
|---|---|
| 预训练跑通 | 能按配置连续训练，loss 曲线持续下降 |
| 瞎猜线标注 | 工作台画出 8.76 参考线（`ln(词表大小)`，minimind 词表约 6400 → 8.76） |
| 降 loss | 训练结束时 loss 进入 **2~3** 区间（数据/规模不同会有偏差，进不去要如实报告） |
| 6 阶段 × 3 子阶段 | 共 18 段按步数切分，每段都有模型备份 |
| 可视化 | 控制台能看到曲线、阶段边界、目标区间、备份清单 |
| 概念理解 | 用自己的话解释预训练 / loss / 梯度下降 / 反向传播 / 学习率（不许抄定义） |

## 为什么瞎猜线是 8.76

交叉熵损失 = `-ln(模型给正确 token 的概率)`。模型完全没学时，对 6400 个词的输出近似均匀，
正确词概率 ≈ 1/6400，于是 `loss ≈ ln(6400) ≈ 8.757` —— 这就是"闭眼瞎猜"的水平，画成红线当基准。
训练的意义就是让 loss 从这条线往下掉：**低于 8.76 = 开始学到东西；落到 2~3 = 学到了语言结构。**

## 训练结构：6 阶段 × 3 子阶段

```
阶段 1..6（按训练进度/学习率调度划分）
 └─ 子阶段 1..3（按步数均分）
      └─ 每段结束：保存 checkpoint → runs/p<阶段>-s<子阶段>/
```

| 阶段 | 目的 | 学习率（示例） |
|---|---|---|
| P1 | 跑通、观察 loss 从 8.76 快速下降 | 3e-4 |
| P2 | 稳定下降 | 3e-4 |
| P3 | 进入平台期，扩 batch | 2e-4 |
| P4 | 学习率衰减 | 1e-4 |
| P5 | 精调下降尾段 | 5e-5 |
| P6 | 收官，验证 loss 是否进入 2~3 | 2e-5 |

每段结束写一行进度到 `.grow-me/loss/loss.csv`（控制台每 5 秒刷新一次）：

```csv
step,loss,phase,sub
100,7.94,1,1
300,6.82,1,2
...
1800,2.41,6,3
```

训练脚本建议直接追加写这个文件（`step,loss,phase,sub` 四列），或在训练日志里 grep 出这两列再转换。

## 执行步骤

1. **探测硬件**：`nvidia-smi` 看显存；无独显 → 用 CPU 小模型或免费 GPU（Colab/Kaggle），别硬撑。
2. **拉代码与数据**：`git clone https://github.com/jingyaogong/minimind`，按仓库 README 准备预训练数据与 tokenizer。
3. **按配置改参数**：显存放不下就减 `batch_size`/`seq_len`、加 `grad_accum`；先跑 20 步确认 loss 在下降。
4. **分段训练**：按 6×3 切步数，每段结束保存 `runs/pX-sY/`（含模型权重 + 训练配置 + 优化器状态）。
5. **喂给控制台**：

```powershell
node grow-me/scripts/console.mjs --runs .\runs --loss .grow-me\loss\loss.csv
```

6. **登记证据**：每段训练结束向控制台登记一条 claim + evidence（日志文件 / 行号 / loss 数值），
   例如 `POST /api/claims {claim:"P3-S2 完成，loss=3.02", evidence:"runs/p3-s2/train.log: loss=3.02"}`。
7. **达标即停**：loss 进入 2~3 就收尾，不为了"看起来更努力"继续烧卡。

## 概念解释（要能用自己的话讲）

- **预训练**：先让模型在海量文本上学会"下一个词最可能是什么"。像小孩先大量听人说话，
  还没人教他语法，但他已经知道什么话顺口。这一步产出的不是"会答题"的模型，而是"懂语言"的底座。
- **Loss（损失）**：模型预测和真实答案差多少的量化。越低说明预测越准；8.76 是"完全瞎猜"，
  2~3 是"基本能猜对上下文"。它是训练唯一要盯的数。
- **梯度下降**：把 loss 想成山谷高度，参数是位置。每次沿"最陡下坡方向"走一小步，反复走就走到谷底。
  步长就是学习率。
- **反向传播**：算"每个参数对 loss 的责任有多大"的方法。答案错了，就从输出往回追，看哪一层、
  哪个参数该改多少 —— 本质是链式法则的高效实现。
- **学习率**：每一步走多大。太大容易跨过谷底来回震荡，太小训练慢得像原地踏步；
  常见做法是前期大、后期小（衰减），本规范 6 个阶段的学习率就是按这个思路排的。

> 交付要求：这些解释要**用自己的话重写**并配自己的例子，抄定义不算完成（规则四：验收要可判定）。

## 风险与如实报告

- 数据没下全 / tokenizer 不匹配 → loss 不降，先查数据而不是调学习率。
- 显存不足（OOM）→ 降 batch/seq、开 grad_accum、换小模型；**不要**把 loss 说成"已达标"。
- 训练中断 → 从最近 `runs/pX-sY` 恢复，并在控制台记录"中断原因"。
- 若最终 loss 停在 3.5 这类"不达标但已收敛"的位置，如实写"未进 2~3，原因是 X"，不许编。
