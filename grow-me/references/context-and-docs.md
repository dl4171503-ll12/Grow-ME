# 工作记录与上下文纪律（grow-me 详解）

## 为什么必须落盘

上下文的成本是"每轮重读"，文件的成本是"需要时读一节"。同一份信息：

- 留在对话里：每次续轮都要重新计费，且会被压缩、被遗忘。
- 写进记录：会话重启、上下文压缩、换 agent 接手时，读一节就恢复，不用重翻代码。

所以 grow-me 的默认动作是：**结论进记录，过程丢出上下文**。

## 位置与命名

```
<工作目录>/.grow-me/                     # 每个项目一个
├── 20261110-1315-skill-v110.md          # 任务记录：yyyyMMdd-HHmm-<slug>.md
├── rounds/                               # 自动测试轮次（规则七）：<slug>-r1.md
├── archive/                              # 已完成任务挪进来，别删（决策依据）
└── logs/
    └── 20261110-1315-test-run.log        # 长输出原文件
```

- slug 用 3–5 个英文词，能一眼认出任务。
- 落点：被委派/子任务 → 任务目录下的 `.grow-me/`；否则项目根；已有上层 `.grow-me/` 就复用最近的，不新开。
- 同一任务反复做，就更新同一份记录，不新开。
- 任务完成后：状态改「完成」，补「交接」节，移到 `archive/`。

## 记录模板（七节，就地覆盖）

```markdown
# <任务名>
状态：进行中 | 暂停（用户插话/等放行） | 阻塞 | 完成
更新：2026-11-10 13:15
工作根：D:\Desktop                # 绝对路径，接手的人不用猜
产物：skills-tools/validate-skills.mjs、skills-tools/AUDIT.md
相关：.grow-me/fixtures/、.grow-me/logs/

## 1. 目标与验收
- 目标：<一句话终态>
- 验收：<1–3 条可判定断言>

## 2. 已定决策
- <决策>：<选择>（来源：用户第 N 轮 / 默认值）

## 3. 事实（路径:行号 → 结论）
- src/foo.ts:42 → 导出函数 X，入参是 (a, b)
- package.json:12 → test 脚本 = vitest run

## 4. 验证
- `node scripts/validate-skill.mjs` → PASS（完整输出见 logs/xxx.log）
- `node -e "..."` → 输出 3 行，关键行：PASS

## 5. DAG
- [x] A 建记录
- [x] B 写脚本
- [~] C 跑测试
- [ ] D 打包

## 6. 下一步
- 只写一条可执行动作（带路径或命令），不写计划段落：例如 `node skills-tools/validate-skills.mjs --all ~/.agents/skills`

## 7. 交接（完成时写）
- 下一个 agent 只看本文件需要知道什么：现状 / 未完成项的具体路径与命令 / 别踩的坑
```

## 读回协议（上下文丢了怎么办）

1. **只读记录**，不读仓库：`read .grow-me/<file>.md`。
2. 记录太大（>150 行）时按标题定位：`grep -n "^## " <file>`，再读对应小节。
3. 记录里没写的事实才去读代码，读到的**立刻补进第 3 节**。
4. 恢复顺序：第 1 节（目标/验收）→ 第 6 节（下一步）→ 第 5 节（进度）→ 缺什么补什么。
5. 不要"为了确认"重读全部记录；按需读节。

## 长输出怎么处理

| 内容 | 处理 |
|---|---|
| 测试/构建输出 | 只留最后 5–10 行 + PASS/FAIL + 完整日志路径 |
| 报错栈 | 只留顶部错误 + 关键帧（带文件行号的 2–3 行） |
| 大 diff | 只在回复里给文件清单 + `git diff --stat`，细节指向文件 |
| 长文件内容 | 绝不贴回；引用 `路径:行号` |

## 记录体积上限

- 单份记录 ≤150 行。超了就该拆：把"事实"按模块拆成 `.grow-me/facts-<area>.md`，主记录只留链接。
- 日志文件不限，但**不许整篇读回**；用 `tail`、`grep` 取需要的行。

## 反乱翻清单（禁 → 替）

| 禁止 | 替代 |
|---|---|
| 整目录 `ls`/`read` 找东西 | `grep`/`glob` 按符号或文件名定位 |
| `cat` 整个文件 | 读命中行 ±30 行 |
| 同一文件读第二遍 | 读记录里的"事实"节 |
| 把大文件/大输出贴回上下文 | 落盘 + 只贴关键行 + 路径 |
| 为"看看有什么"读无关文件 | 先能说出要解决哪个问题，否则不读 |
| 反复复述自己刚做过什么 | 更新记录，回复里只留 ≤5 行摘要 |
| 同一命令跑两遍（代码没变） | 记录里写结果，需要时引用 |

## 清理与归档

- 完成任务 → 状态改「完成」+ 补交接 → 移入 `archive/`。
- 项目级常驻知识（架构决策、约定）不要留在任务记录里，提炼进 `AGENTS.md` 或 `docs/adr/`。
- `.grow-me/` 是否入库：默认加 `.gitignore`；需要团队共享时再提交 archive。
